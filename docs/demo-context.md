## 2. 시간순 이야기 (실제로 일어난 순서)

**3월 8일, 노션 파이프라인.** "새 할일 등록해줘"라고 하면 Claude가 노션에 큰 할일과 세부 태스크를 만들고 시나리오를 쓴다. 사람은 노션 체크박스 두 개(시나리오검수, 개발구현방향)만 누른다. 검토는 사람, 개발은 AI. 몇 사이클 돌리고 멈췄다. 한계는 노션이 코드 리뷰 도구가 아니라는 것, 토큰 비용, 그리고 에이전트와 사람이 같은 노션 계정이라 체크박스를 누가 눌렀는지 구분이 안 된다는 것(승인 관문이 구조가 아니라 약속이었다).

**3월 29일, 역할별 에이전트.** 코드로 돌아와 `.claude/agents/`에 역할별 에이전트를 뒀다. UI 에이전트, 보안 에이전트(방어자와 공격자 두 관점, 서로 결과를 안 봄), 코드 리뷰, FSD 검사 등. 리뷰 결과는 대화가 아니라 파일(`.claude/project/reviews/`)로 남기고, 메인 세션만 읽는다. 노션 이후로는 이렇게 세션을 나눠 관리하는 쪽으로만 쓴다. 팀에서 같이 쓸 때도 에이전트 관련 규칙은 md 파일로 적어 두고 통일하려고 했다.

**7월, 약속을 구조로.** 3월에 걸어 둔 포맷 훅이 넉 달 동안 안 돌고 있었다는 걸 발견했다(설정 파일 이름 오타, 없는 환경 변수). 그 뒤로 기계가 매번 같은 답을 낼 수 있는 건 AI한테 부탁하지 않고 구조로 막는다. FSD 레이어 규칙은 lint로, 문서의 파일 경로는 CI 검사로.

**10월(이번 주), 코드 지도와 QATester.** 코드 전체를 Graphify로 그래프로 그리고, 그 위에 테스트 시나리오가 실제로 검증하는 파일을 색으로 칠했다. 빈 곳은 에이전트가 시나리오를 제안하고, 사람이 고르면 다른 에이전트가 테스트를 쓰고, 실패하면 또 다른 에이전트가 원인을 판정한다. 테스트를 쓰는 에이전트는 훅으로 앱 코드 수정이 막혀 있다.

## 3. 4부의 QATester, 어디까지 자동인가

이름은 "테스트 시나리오 장부" 또는 "검증 지도"라고 부른다. **"E2E 테스트 자동화"라고 부르지 않는다.** 장부에 걸린 테스트는 단위, 통합, E2E가 섞여 있고, 핵심은 테스트 코드 생성이 아니라 장부가 먼저 알고 역할을 나눈 것이다.

자동으로 도는 것:

- 코드가 바뀌면 import로 연결된 시나리오만 "재검증 필요"가 된다. 연결은 기계가 뽑는다
- 나이틀리(GitHub Actions, 매일 03:00 KST, dev 기준)가 재검증 필요한 것만 다시 돌리고 보고서를 남긴다. **이슈는 만들지 않는다**
- 근거(facts)는 지우지 않고 쌓인다. 커밋, 시각, 파일 해시, 걸린 테스트 제목

사람이 부를 때만 도는 것(`/qa-sweep`, 에이전트 셋은 서로 결과를 안 봄):

- 시나리오 제안(qa-scenario-writer): 제안 파일만 쓴다. 장부에 넣는 건 사람이 고른다
- 테스트 작성(qa-test-author): 테스트 파일만 쓴다. 앱 코드 수정은 훅이 막는다(종료 코드 2)
- 실패 판정(qa-judge): 앱 버그, 테스트 버그, 주장 과대, 외부 흔들림, 환경으로 가른다. 읽기 전용

일부러 안 하는 것: 이슈 자동 등록, 코드 자동 수정. 사람 확인 10건 이상, 앱 버그 판정 정확도 80% 이상이 쌓이면 이슈 초안부터 검토한다.

4부 4번(훅 차단)은 settings.json과 무관하다. 가드 훅은 에이전트 파일 머리말(`.claude/agents/qa-test-author.md`)에 걸려 있고, 시연은 에이전트를 안 부르고 스크립트에 직접 입력을 넣는다. 레포만 있으면 된다.

레포에 있어서 따로 옮길 필요 없는 것: 제안 파일 `qa-knowledge/proposals/2026-10-14-semantic-search-v2.json`, 나이틀리 보고서 `qa-knowledge/reports/2026-10-14.md`, 장부 `qa-knowledge/scenarios.json`, 포맷 데모 원본 `docs/demo/formatDemo.ts.txt`.

## 6. 이 컴퓨터의 Claude 세션이 지킬 것

해도 되는 것:

- `node scripts/qa/qa.mjs status`, `show`, `gaps` (읽기만)
- 훅 차단 시연 명령 (대본 4부에 있음)
- `pnpm --filter @smart-bookmark/web lint:fsd` (error 1건이 정상, 일부러 넣은 샘플)
- 포맷 훅 시연: `formatDemo.ts`를 고치게 한 뒤 `cp docs/demo/formatDemo.ts.txt apps/web/src/shared/lib/formatDemo.ts`로 원복

하면 안 되는 것:

- `demo/harness-talk`를 dev나 main에 PR이나 머지. FSD 위반 샘플(`countByQuery.ts`)이 들어 있다
- `formatDemo.ts` 커밋. untracked가 정상이다
- `git push --no-verify`
- `.env.local`, `.claude/settings.local.json`을 화면에 열기
- 장부(`scenarios.json`)에 시나리오를 넣거나 이슈를 만드는 것. 사람이 말할 때만
- 발표 중 에이전트를 실제로 부르는 것. 대본은 전부 라이브 호출 없이 짜여 있다

## 7. 용어

| 말           | 뜻                                                                                                                              |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| 하네스       | 규칙(CLAUDE.md) + 자동 검사(훅, CI) + 사람 승인 관문. 에이전트는 부품 하나                                                      |
| 장부         | `qa-knowledge/` 아래 시나리오, 근거, 발견 파일                                                                                  |
| 시나리오     | 사용자 동작 단위의 주장. "비회원은 20개까지 저장하고 21번째에 안내가 뜬다"                                                      |
| 연결 (links) | 시나리오가 의존하는 코드 파일. 기계가 import 관계에서 뽑는다                                                                    |
| 근거 (facts) | 실행 결과와 커밋, 시각, 파일 해시. 지우지 않는다                                                                                |
| 재검증 필요  | 마지막 통과 뒤 연결된 코드가 바뀐 상태                                                                                          |
| 검증 지도    | 코드 그래프 위에 장부 상태를 색으로 겹친 html. 초록 검증됨, 노랑 부분 또는 재검증 필요, 빨강 실패, 회색 아무 시나리오도 안 닿음 |
