description: 따로 돌린 보안 리뷰 결과(기본, 공격자 관점, CodeQL, 의존성)를 개발 세션에서 하나로 종합한다. 사람이 "보안 리뷰 종합해줘"라고 할 때만 실행한다.
allowed-tools: Read, Write, Bash, Grep

## 원칙

- 종합은 개발 세션(메인)만 한다. 리뷰 에이전트에게 다른 리뷰를 보여주지 않는다
- 사람이 요청했을 때만 한다. 종합 결과를 근거로 수정 작업을 시작하지 않는다. 무엇을 고칠지는 사람이 고른다
- 각 리뷰의 원본 파일은 고치지 않는다

## 입력 모으기

사용자가 날짜나 파일을 지정했으면 그것만 쓴다. 지정이 없으면 가장 최근 것을 쓴다.

1. 기본 리뷰: `.claude/project/reviews/security-review-*.md`
2. 공격자 관점 리뷰: `.claude/project/reviews/security-deep-*.md` (없으면 "심층 리뷰 없음"으로 표시하고 진행)
3. CodeQL: `gh api "repos/{owner}/{repo}/code-scanning/alerts?state=open&per_page=100"` — 규칙 ID, 심각도, 파일:줄
4. 의존성: `pnpm audit --prod --json`의 critical/high

두 리뷰의 대상이 다르면(다른 파일, 다른 날짜의 코드) 종합하지 말고 그 사실을 먼저 알린다.

## 같은 문제 판정

파일과 줄 범위가 겹치고, 같은 원인(같은 입력이 같은 위험 지점에 닿음)을 가리키면 같은 문제로 본다.
제목이나 분류명이 달라도 원인이 같으면 같은 문제다. 애매하면 "같은 문제일 수 있음"으로 따로 표시한다.

## 출력

`.claude/project/reviews/security-summary-YYYY-MM-DD.md`에 저장하고, 화면에는 1번 표와 건수만 보여준다.

```markdown
# 보안 리뷰 종합 (YYYY-MM-DD)

입력: [사용한 파일 목록, CodeQL 조회 시각, audit 실행 여부]

## 1. 여러 곳에서 찾음 (신뢰도 높음, 먼저 볼 것)

| 문제 | 위치 | 기본 | 공격자 | CodeQL | 심각도(각각) |

## 2. 한 곳에서만 찾음 (근거 확인 필요)

| 문제 | 위치 | 찾은 곳 | 근거 경로 | 다른 쪽이 놓친 이유 추정 |

## 3. 판단이 엇갈림 (사람이 결정)

| 문제 | 위치 | 기본의 판단 | 공격자의 판단 | 엇갈린 지점 |

## 4. 의존성

| 심각도 | 패키지 | 패치 버전 |

## 5. 아무도 확인하지 못한 영역

[각 리뷰의 "확인 불가" 항목 모음]
```

"한 곳에서만 찾음"은 오탐일 수도, 다른 쪽이 놓친 것일 수도 있다. 어느 쪽인지 단정하지 말고,
코드를 직접 열어 근거 경로가 실제로 성립하는지만 한 줄로 덧붙인다.
