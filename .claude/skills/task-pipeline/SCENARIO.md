# 테스트 시나리오 작성법

task-pipeline에서 태스크 페이지의 `## 테스트 시나리오`를 쓸 때의 기준이다. 흐름(언제 쓰고, 언제 승인받는지)은 SKILL.md에 있다.

## 원칙

- **사용자가 눈으로 확인할 수 있는 동작**으로 쓴다. "함수 X가 Y를 반환한다"가 아니라 "저장하면 카드에 '방금 전'이 보인다".
- 한 시나리오는 하나의 확인 가능한 결과만 말한다. 여러 결과가 섞이면 나눈다.
- 숫자와 조건은 기획서(PROJECT_PLAN.md)와 코드에서 가져온다. 추정이면 "가정:"으로 따로 적는다.
- 측정 기준이 없는 말(빠르게, 자연스럽게, 끊김 없이)은 쓰지 않는다.

## 형식

```
### [정상] 저장 직후 상대 시간이 보인다
- Given: 북마크를 방금 저장했다
- When: 상세 패널을 연다
- Then: '저장' 항목에 '방금 전'이 보인다
```

## 빠뜨리지 않을 케이스

- **정상:** 기본 흐름
- **오류:** 실패, 권한 없음, 잘못된 입력
- **엣지:** 경계값(0, 최대, 하루 경계, 한국 자정), 빈 상태, 아주 긴 값

## 테스트로 옮길 때

- 시나리오 하나가 테스트 하나 이상이 된다. 테스트 이름에 시나리오 문장을 그대로 쓴다.
- 단위 테스트로 확인하지 못하는 부분(화면에 실제로 보이는지)은 완료 댓글에 "사람이 화면에서 확인할 것"으로 남긴다.
